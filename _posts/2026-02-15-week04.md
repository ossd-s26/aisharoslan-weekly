## Git and Project Evaluation

The git exercises we did in class were a great refresher and eye opener for me. I'm a regular git user, I've learned to properly use it when I did my summer internship last year. So, this class was a great deeper dive into the git commands I commonly use but also ones I rarely use or don't know about and the proper terminologies for them. For example, git restore, git log, git add, git commit, git push, and git diff. I've never dove into the git object folder either and it was interesting to see how files were stored or tracked by git.

Project evaluation is a crucial part of open source to ensure a smoother and better experience when contributing. It has been interesting looking through several projects and how they're different from each other. Some have really large numbers of contributors and some much less. For example, Nautilus Trader had 100+ while sci-kit had 3000+. Seems to indicate that more niche projects have lesser contributors than those that are more widely used. The way their repositories are organized are also different. For example, Exercism had multiple repositories and GIMP used GitLab instead of GitHub for their repository. <!--more-->

Regarding the different projects I've seen, I'm surprised to see so many different projects in such different areas. Some of which I'm excited to contribute to but also some of which I will try to avoid due to lack of domain expertise and project responsiveness. I'm most excited to learn and practice contributing to open source projects, learning how to communicate, contribute, read, and write code or documentation. I think the biggest challenge for me would be choosing a project I actually use and understand. The idea of reading through an unknown codebase is a little daunting but that's part of the job of being a software developer. Another challenge would probably be choosing where/what/how exactly I want to contribute and being able to defend a decision or reason through it to more experienced contributors. I plan to overcome these challenges by starting to scout for open source projects I'm truly interested in, that I understand, and are actively responsive. I will take time to look at pull requests, issues, and documentation to make sure I'm doing things the right way for the project and if I make a mistake when contributing, at least I learn from it and know how to fix my approach.
